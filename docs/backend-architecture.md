# 后端架构文档（backend-architecture.md）

## 1. 定位与约束

- 个人学习项目，非生产级，先跑通最小闭环，不做过度设计。
- 形态：桌面 AI Agent 的后端服务，搭载遐蝶人格与记忆，不是普通聊天机器人。
- 后端是独立的 Python 服务，负责 Agent 编排、模型调用、工具系统、记忆、RAG、MCP、TTS 和权限控制。
- 前端（Electron）只做表现层与交互，通过 HTTP + WebSocket 调用后端，不持有 API Key。
- 前后端分离，后端未来可跑在 Linux 电脑或云服务器，前端只改连接地址。
- 开发期后端可独立启动，打包后由桌面壳（Electron 主进程）拉起。
- 能力示例：陪聊、游戏每日任务、汇报今日天气、查询新闻、按实时汇率生成外贸财务报表、生成各类办公文档，长期还包括优化自己。
- 能力目标：AI 聊天、多模型接入、长期记忆、RAG 检索、工具调用、MCP 扩展、技能系统、TTS 语音。
- 模型走 API，支持 OpenAI-compatible / Anthropic-like 适配，默认 DeepSeek，预算约 30 元。
- TTS 走 API，偶尔开启，优先音色自然。
- 无语音输入，预留 ASR 接口。
- 本地嵌入模型：`D:\my_local_model\paraphrase-multilingual-MiniLM-L12-v2`，路径配置化。
- 向量库用 ChromaDB，开发者熟悉，学习成本低。
- 人格预设结构化，长期记忆默默记住，可审计。
- 模块化：先做静态模块注册，后期再升级为类似 VSCode 的插件扩展。
- 允许分多个版本重构实现，但不要过度重构。

## 2. 总体分层

```text
Python 后端服务（Agent 运行时）
  ├── HTTP 接口
  ├── WebSocket 接口（AG-UI 事件流）
  ├── Agent 编排（函数调用循环）
  ├── 模型适配层
  │     └── OpenAI-compatible / Anthropic-like
  ├── 工具系统
  │     ├── 内置工具
  │     └── MCP 扩展
  ├── 技能系统
  ├── 记忆系统
  │     ├── 用户画像
  │     ├── 长期记忆
  │     ├── 导入文档检索（RAG）
  │     └── worldbook 检索
  ├── 定时任务 / 游戏自动化（预留）
  ├── TTS 模块
  ├── ASR 预留模块
  ├── 权限控制
  ├── 配置模块
  ├── 插件系统（后期）
  └── 数据层
        ├── SQLite
        ├── ChromaDB
        └── 本地嵌入模型
```

## 3. 目录结构

```text
soul-mate/
├── backend/                    # Python 后端服务（本文档）
│   ├── app/
│   │   ├── main.py             # 服务入口：装配模块、启动 HTTP / WebSocket
│   │   ├── config.py           # 配置与密钥加载
│   │   ├── api/                # HTTP 路由、WebSocket / AG-UI 事件端点
│   │   ├── agent/              # 编排：函数调用循环、上下文组装、事件推送
│   │   ├── models/             # 模型适配层：base / openai_compatible / anthropic_like
│   │   ├── tools/              # 内置工具，按统一 schema 注册
│   │   ├── mcp/                # MCP 客户端与连接管理
│   │   ├── skills/             # 技能：多步流程封装，静态注册
│   │   ├── memory/             # 抽取、存储、检索、文档、worldbook、审计
│   │   ├── persona/            # 人格配置与注入
│   │   ├── tts/                # TTS 适配与按句切分
│   │   ├── asr/                # ASR 预留
│   │   ├── tasks/              # 定时任务 / 游戏自动化（预留）
│   │   ├── permission/         # 权限控制
│   │   └── storage/            # SQLite 连接、表结构、迁移
│   ├── data/                   # 运行数据（不入 Git）
│   │   ├── soul_mate.db
│   │   ├── chroma/
│   │   └── documents/
│   ├── config.local.yaml       # 本地配置与 API Key（不入 Git）
│   ├── requirements.txt
│   └── README.md
├── frontend/                   # Electron 桌面应用（见 frontend-architecture.md）
└── docs/
```

约定：

- 模块划分与 `app/` 下的目录一一对应，新增模块先建目录再挂到 `main.py`。
- `data/`、`config.local.yaml` 不进版本库。
- 本地嵌入模型不进仓库，路径写在配置里（Windows 和 Linux 不同）。
- 插件目录等进入插件化阶段再加，现在不预建。

## 4. 模块划分

### 4.1 config

- 管理 API Key、模型名、TTS 音色、服务地址、路径配置。
- 配置本地文件，不提交到 Git。
- 路径配置化，Windows 和 Linux 不同。

### 4.2 api

- FastAPI 提供 HTTP 和 WebSocket。
- WebSocket 负责流式文本、音频、状态、工具调用、记忆更新等 AG-UI 事件。
- HTTP 负责配置、人格、记忆管理、任务、健康检查。
- 只监听本机，默认不对局域网开放。

### 4.3 agent

- 函数调用循环：模型输出 → 工具调用 → 结果回填 → 继续生成。
- 上下文管理：最近 N 轮 + 滚动摘要 + 记忆注入。
- 事件流用 AG-UI：把模型回复、工具调用、状态变化实时推送给前端。
- 输出：流式文本 + 情绪标签 + 动作标签 + 工具调用状态。
- 先跑通单步工具调用，再考虑多步规划。

### 4.4 models（模型适配层）

- 统一接口：`generate(messages, tools, stream=True)`。
- 支持 OpenAI-compatible / Anthropic-like 两种协议风格。
- 多模型接入：模型名、Base URL、Key 可配置，按场景选用。
- 流式输出。
- 成本监控：token 统计、预算告警。

### 4.5 tools（工具系统）

- 内置工具：文件操作、网页获取、搜索、天气、文档生成（Excel / PPT / PDF / Word）、翻译、记账、历史回忆、出行规划。
- 后续扩展：游戏每日任务、游戏自动化。
- 工具按统一 schema 注册，由模型通过函数调用选择。
- 危险操作交给权限控制。

### 4.6 mcp（MCP 扩展）

- 通过 MCP 接入外部工具与资源。
- 作为内置工具之外的扩展入口。
- 连接配置化，按需启用。

### 4.7 skills（技能系统）

- 技能把常用的多步流程封装成可复用单元。
- 先静态注册，后期再考虑动态加载。
- 可被定时任务调度执行。

### 4.8 memory（记忆系统）

- 结构化记忆：SQLite。
- 向量记忆：ChromaDB。
- 本地嵌入：`paraphrase-multilingual-MiniLM-L12-v2`。
- 用户画像：从长期交互中沉淀的稳定信息，可查看、可编辑。
- 导入文档检索：导入文档切分后嵌入，按需检索（RAG）。
- worldbook 检索：按条目 / 关键词命中设定类信息。
- 抽取：异步，不阻塞回复。更怕记不住，所以每轮轻量抽取关键偏好 / 事实，对话结束批量总结。
- 存储：一句话一条，合并去重，冲突更新。
- 检索：语义 + 时间 + 重要性，top 8–12，重排后注入。
- 审计：查看、编辑、删除、回滚。
- 冲突消解：人格优先，记忆标注“用户偏好变化”。

### 4.9 persona（人格）

- 结构化人格配置：名字（少司缘）、背景、语气、口头禅、喜好、禁忌、关系定位。
- 默认静态，不随对话自动漂移。
- 注入策略：摘要 + 关键字段，控制 token。
- 与记忆冲突时，人格优先，但可参考记忆调整表达。

### 4.10 tts

- 优先音色自然，流式合成。
- 国内可选火山引擎、阿里云、讯飞等。
- 按句切分，边生成边发音频块。
- 成本监控，偶尔开启。
- 口型不需要音素，前端用振幅驱动。

### 4.11 asr 预留

- 暂时不实现。
- 定义接口：`transcribe(audio) -> text`。
- 未来可接 API 或本地模型。

### 4.12 tasks（定时任务 / 游戏自动化，预留）

- 预留事件总线 / 调度器接口。
- 暂不实现主动行为。
- 未来支持定时问候、记忆整理、关系状态更新、游戏每日任务与自动化。

### 4.13 permission（权限控制）

- 危险操作（写文件、执行命令、联网提交等）先确认再执行。
- 权限粒度可按工具 / 目录 / 域名配置。
- 工具调用记录留痕，便于回溯。

### 4.14 plugins（插件系统，后期）

- 目标：像 VSCode 一样通过添加插件扩展功能。
- 先做静态注册，不提前实现动态加载。

## 5. 数据存储

### 5.1 SQLite

- **会话表**：会话 ID、时间、标题。
- **消息表**：会话 ID、角色、内容、时间、token 统计。
- **记忆事实表**：ID、类型、内容、重要性、时间、状态。
- **用户画像表**：字段化的稳定信息。
- **人格配置表**：结构化字段。
- **任务表**：定时任务 / 计划任务。
- **审计表**：记忆变更记录、配置变更记录、工具调用记录。
- **成本表**：token 消耗、TTS 字符数、时间。

### 5.2 ChromaDB

- 持久化本地目录。
- 存储记忆向量、导入文档向量、worldbook 向量。
- 元数据：时间、类型、重要性、来源。
- 与 SQLite 中的 ID 关联。
- 迁移时复制目录即可。

### 5.3 本地嵌入

- 路径配置化，Windows 和 Linux 不同。
- 加载 `paraphrase-multilingual-MiniLM-L12-v2`。
- 服务记忆、导入文档、worldbook 三类检索。
- 轻薄本可跑，但注意内存。
- 未来可切 API 嵌入。

## 6. 记忆与检索策略（更怕记不住）

- **抽取频率**：每轮异步轻量抽取 + 对话结束批量总结。
- **抽取内容**：用户偏好、事实、关键事件、情绪标签。
- **存储粒度**：一句话一条，便于检索和编辑。
- **召回数量**：top 8–12，优先保证记住。
- **重排**：语义相似度 + 时间衰减 + 重要性。
- **冲突**：新记忆覆盖旧记忆，保留变更记录。
- **审计**：必须可查看、编辑、删除。
- **成本**：上下文压缩，但记忆抽取和召回不能太激进。
- **来源**：用户画像、长期记忆、导入文档 / worldbook，检索结果合并后再注入。

## 7. Agent 编排与上下文

- **系统提示**：人格摘要 + 关键字段。
- **记忆注入**：用户画像 + 召回的相关记忆。
- **历史上下文**：最近 5–8 轮 + 滚动摘要。
- **工具调用**：函数调用循环，工具结果回填后继续生成。
- **输出**：流式文本 + 情绪标签 + 动作标签 + 工具调用状态。
- **事件**：通过 AG-UI 事件流实时推送。
- **成本**：监控 token，30 元预算下压缩历史，但记忆优先。

## 8. TTS 策略

- 偶尔开启，优先音色自然。
- 流式合成，按句发送音频块。
- 前端播放并驱动口型。
- 成本监控，避免频繁长文本。

## 9. 安全与权限

- API Key 本地保存，不提交 Git。
- 工具调用默认最小权限，危险操作需确认。
- 工具调用、记忆变更、配置变更都要可审计。

## 10. 迭代与迁移

- 先跑通最小闭环：文字聊天 + Live2D + 口型 + 记忆 + 人格 + 工具调用 + TTS 语音。
- 分版本迭代，技能系统、定时任务、游戏自动化、插件化先预留接口，不提前实现。
- 数据文件可导出：SQLite + ChromaDB 目录。
- 后端服务与数据目录分离，迁移时复制数据目录即可。
- 未来可容器化，Docker Compose 一键部署。

## 11. 后端注意事项汇总

- API Key 本地保存，不提交 Git。
- 断网时不可用，返回明确错误。
- 日志、成本、记忆命中、prompt 版本要可观测。
- 模块化，静态注册，不要过早做动态插件。
- 记忆审计必须做，否则长期失控。
- 人格与记忆冲突要有消解策略。
- 工具调用要有权限确认与审计记录，否则长期失控。
- 预留 ASR、本地模型、定时任务、游戏自动化、插件化升级空间。
