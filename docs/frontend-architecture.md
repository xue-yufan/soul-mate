# 前端架构文档（frontend-architecture.md）

## 1. 定位与约束

- 个人学习项目，非生产级，先跑通最小闭环，不做过度设计。
- 桌面应用形态：打开后出现 Live2D 形象、聊天窗口、任务页、侧边栏、语音开关。
- 桌面壳：Electron + TypeScript + Vite。
- 必须支持透明、置顶、托盘、精致 UI。
- 前端只做表现层与交互：不持有 API Key，不直接调用 LLM / TTS。
- 业务能力全部在 Python 后端，前端通过 HTTP + WebSocket 调用（见 backend-architecture.md）。
- 主进程负责桌面壳能力与后端服务的启动、守护，渲染进程不直接管进程。
- 前后端分离，后端未来可迁移到 Linux 电脑或云服务器，前端只改连接地址。
- 文字与语音输出并行，语音输出可开关，暂不做语音输入，但预留接口。

## 2. 总体分层

```text
Electron 桌面应用
  ├── 主进程
  │     ├── 窗口管理（Live2D 窗口 / 聊天窗口 / 设置页 / 任务页）
  │     ├── 桌面能力（透明、置顶、托盘、点击穿透、拖拽、系统通知）
  │     ├── 后端服务生命周期（启动、守护、地址下发）
  │     └── IPC（contextBridge / preload）
  └── 渲染进程
        ├── Live2D 渲染层（PixiJS + pixi-live2d-display）
        ├── 音频层（Web Audio API）
        ├── 交互状态机
        ├── 聊天 UI
        ├── 任务页
        ├── 侧边栏
        ├── 记忆审计 UI
        ├── 设置 UI
        └── 通信层（HTTP + WebSocket / AG-UI 事件流）

Python 后端服务（见 backend-architecture.md）
  └── Agent 编排 / 模型适配 / 工具 / 记忆 / RAG / MCP / TTS / 权限
```

```text
│   ├── electron/

│   │   │   ├── index.ts        # 主进程入口：应用生命周期
│   │   │   ├── windows.ts      # 各窗口创建与管理

│   │   │   ├── backend.ts      # 启动与守护后端服务，下发地址与健康状态
│   │   │   └── ipc.ts          # IPC 通道注册
│   │   └── preload/

│   │   ├── settings/           # 设置页
│   │   ├── sidebar/            # 侧边栏
│   │   ├── memory/             # 记忆审计页

│   │   ├── ui/                 # 通用组件与设计系统
│   │   └── types/              # 事件与数据结构类型（与后端对齐）

└── docs/
```

约定：

- 渲染层代码只依赖 `electron/preload` 暴露的接口，不直接引用 `electron/main`。
- 后端连接地址由主进程下发，渲染层不写死端口。
- Live2D 模型、图标等大资源放 `public/`，不写进业务代码。
- 与后端共享的事件类型统一放 `src/types/`，避免两边各写一份。

## 4. 主进程与渲染进程

主进程负责窗口、托盘、桌面能力和后端服务生命周期；渲染进程负责表现与交互。两者之间通过 preload + contextBridge 通信，渲染进程不直接使用 Node / Electron 原生 API。

### 4.1 桌面能力（主进程实现，渲染层通过 IPC 调用）

- 窗口透明
- 窗口置顶
- 托盘图标与菜单
- 点击穿透区域
- 窗口拖拽
- 窗口尺寸 / 位置
- 开机自启（可选）
- 系统通知（可选）

### 4.2 窗口划分

- **Live2D 窗口**：透明、无边框，可置顶，立绘区域支持点击穿透。
- **聊天窗口**：气泡、时间、状态、语音开关、工具调用展示。
- **任务页**：定时任务 / 游戏自动化的任务列表与执行状态。
- **设置页**：后端地址、模型与 Key、TTS 开关、音色、成本显示、日志入口。
- **侧边栏**：会话列表与功能入口。
- **记忆审计页**：查看、编辑、删除记忆，查看用户画像与人格配置。

### 4.3 注意事项

- 透明窗口 + WebGL 在 Windows 上可能有黑边、阴影异常、点击穿透不准，必须早测。
- 置顶时注意焦点管理，避免聊天框无法输入。
- 点击穿透要按区域控制：立绘区域穿透，聊天区域可交互。
- 托盘菜单要与主窗口状态同步。
- 多窗口共享状态要统一，避免各窗口各自维护一份。
- 后端启动失败时要给出明确提示，不能静默失败。

## 5. Live2D 与口型

### 5.1 渲染

- 使用 PixiJS + pixi-live2d-display 驱动 Live2D。
- 模型资源本地加载，注意跨平台路径。
- 表情、动作、待机动画由前端驱动。
- 情绪标签由后端随文本流下发，前端解析后切换表情 / 动作。

### 5.2 口型

- 只做张合，不需要 Viseme。
- 音频播放时，用 Web Audio API 分析振幅。
- 振幅 → RMS / 包络 → 平滑 → 映射到 ParamMouthOpenY。
- 必须做缓冲和平滑，否则嘴巴抖动。
- 口型跟音频走，不跟文字走。

### 5.3 注意事项

- 音频块可能分片到达，要维护播放队列。
- 打断时立即停止音频、清空队列、复位口型。
- 语音关闭时，口型静止，只走文字链路。

## 6. 交互状态机

建议至少包含这些状态：

- 空闲
- 思考中
- 工具调用中
- 说话中
- 打断
- 离线
- 语音关闭 / 开启

文字与语音并行时：

- 后端流式返回文本。
- 后端按句切分并调用 TTS。
- 前端边收文字边显示，边收音频边播放。
- 音频播放时驱动口型。
- 工具调用时在聊天窗口展示调用与结果。
- 用户关闭语音时，只显示文字，不播放音频。

## 7. UI 与精致度

- UI 框架：React 或 Vue，配 Tailwind 或同类设计系统。
- 状态管理：Zustand / Pinia，保持轻量。
- 动效：Framer Motion 或同类，但不要过度。
- 聊天界面：气泡、时间、状态、语音开关、工具调用过程。
- 任务页：任务列表、执行状态、手动触发。
- 侧边栏：会话列表与功能入口。
- 记忆审计页：查看、编辑、删除记忆，查看用户画像与人格配置。
- 设置页：后端地址、模型与 Key、TTS 开关、音色、成本显示、日志入口。

## 8. 通信协议

### 8.1 WebSocket（用于流式交互）

| 消息类型 | 说明 |
| --- | --- |
| `text_delta` | 文本增量 |
| `text_done` | 文本结束 |
| `audio_chunk` | 音频块 |
| `audio_done` | 音频结束 |
| `emotion` | 情绪 / 动作标签 |
| `state` | 状态变化 |
| `tool_call` | 工具调用开始 |
| `tool_result` | 工具调用结果 |
| `memory_update` | 记忆更新通知 |
| `error` | 错误 |

### 8.2 HTTP（用于配置与管理）

| 接口 | 说明 |
| --- | --- |
| `GET /health` | 健康检查 |
| `GET /config` / `POST /config` | 配置读写 |
| `GET /persona` / `POST /persona` | 人格配置读写 |
| `GET /memories` / `POST /memories` / `DELETE /memories/{id}` | 记忆管理 |
| `GET /tasks` / `POST /tasks/{id}/run` | 任务列表与触发 |

### 8.3 注意事项

- 协议要版本化，先跑最小闭环，但消息类型预留。
- 前端连接地址从配置读取，本地是 localhost，未来是局域网 IP 或域名。
- 断网或后端不可用时显示离线状态，不本地生成回复。
- 音频、工具结果等大块数据走 WebSocket，配置与管理走 HTTP。

## 9. 前端注意事项汇总

- 不持有 API Key。
- 不直接调用 LLM / TTS，业务能力都走后端。
- 业务代码不依赖 Electron 原生 API，统一走 preload / IPC。
- 透明窗口 + Live2D 是最大风险，早测。
- 音频队列、打断、口型平滑要重点调。
- 工具调用过程要可见，长时间执行要有状态反馈。
- 记忆审计页必须做，否则长期记忆失控无法纠正。
- 性能：轻薄本上控制帧率、内存、音频缓冲。
