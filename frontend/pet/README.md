# 桌宠（3D desktop pet）

**这是正式代码区，不是临时试验场。** 目标形态是一个独立的桌面宠物应用：透明无边框窗口 + 置顶 +
区域点击穿透 + three.js 渲染她的形象。它和主应用（`frontend/src` 那套 Vue 界面）**是两个应用**，
共用同一个后端（`127.0.0.1:8000`）。

## 现阶段要的是"知识"，不是"代码"

P3 要回答的是平台问题（清单见 [`docs/improvement-plan.md`](../../docs/improvement-plan.md) 的 P3）：
透明窗口有没有黑边、置顶抢不抢焦点、点击穿透准不准、WebGL 在透明窗口下的 alpha 合成对不对、
帧率和显存能不能接受。

所以这里**故意不引 three.js、不走打包**，只用裸 WebGL 画一个三角形——要回答的是平台问题，
不是渲染库问题，变量越少结论越干净。也正因为如此，**现阶段不追求代码质量**：
`pet/**` 暂时排除在 eslint / tsconfig 之外，什么时候收回来见文末。

## 跑起来

```powershell
cd frontend\pet

# A. 独立装一份依赖（它是独立应用，将来自己打包，所以这条是主线）
npm install
npm start

# B. 验证阶段也可以直接用主项目那份 electron（零安装，版本天然一致）
npm run start:shared
```

`package.json` 里 electron 钉的是 **32.3.3**，也就是主项目 `node_modules/electron` 里实际装到的
那个版本。透明窗口 + WebGL 的行为和 Chromium 版本强相关，别随手升级这一个。

## 对照组：一次只改一个变量

`transparent` / `frame` 只能在创建窗口时决定，所以对照组要重开一次进程：

| 命令 | 和默认比，差在哪 | 用来回答 |
| --- | --- | --- |
| `npm start` | 目标配置（透明 + 无边框 + 玻璃 + WebGL） | 我们要的那套到底行不行 |
| `npm run start:opaque` | 不透明窗口 | 黑边 / 残影是不是透明引起的 |
| `npm run start:framed` | 带系统边框 | 无边框是不是那些异常的来源 |
| `npm run start:no-glass` | 只关玻璃 | 清单第 5 条：模糊到底有没有生效 |
| `npm run start:no-webgl` | 只关 WebGL | 清单第 7 条：边缘发黑是不是 WebGL 引起的 |
| `npm run start:plain` | 玻璃和 WebGL 都关 | 粗筛：它也有问题 ⇒ 这两个都不是原因 |
| `npm start -- --no-top` | 启动时就不置顶 | 和运行中按 <kbd>T</kbd> 等价，冷启动时省一步 |
| `npm start -- --disable-gpu` | 软件渲染 | 是不是显卡驱动的问题 |

⚠️ `--framed` 这一条有个平台事实要记住：**Windows 上透明只在无边框窗口生效**
（Electron 文档原话："On Windows, does not work unless the window is frameless"），
所以 `--framed` 会**同时把透明也关掉**——它一次改了两个变量。程序启动时会打一行警告提醒，
别把它的结果当成"边框不是原因"的证据。

玻璃和 WebGL 在页面上就能**单独**切（`G` / `W` 按钮和快捷键，不用重启）；CLI 那两条的价值是
**冷启动时就已经是那个配置**，用来排除"只有开机那一刻的合成路径才出问题"这种情况。

同理，**默认配置下"看不出透明"是正常的**：背景层压着 0.72 的不透明度，桌面只是隐隐透出来。
想看干净的透明效果，点 HUD 里的「背景层」把它关掉。

## 界面上那几个开关，各自对应什么问题

- **窗口几何**：360×576 的小竖窗（和立绘 800×1279 同比），贴在**主屏左侧靠下**、
  避开任务栏。验证阶段写死在 `main.cjs` 顶部（`WIN_WIDTH/HEIGHT/MARGIN`）；正式版应该
  记住用户拖到的位置（架构文档里的"窗口尺寸 / 位置"）。
- **背景层**（按钮 / 默认开着）：关掉之后整个窗口只剩玻璃面板和那个三角形——这才是纯粹的
  「桌面能不能透出来」测试。开着时是主应用现在的观感。
- **玻璃 (G)**：`backdrop-filter` 开 / 关。两组面板（玻璃 vs 对照）永远都能直接对比。
- **WebGL alpha (W)**：在 `premultipliedAlpha: true/false` 之间切换（会重建 canvas 和上下文）。
  透明窗口里 WebGL 边缘发黑、发灰，十有八九是这一条配错了。
- **丢上下文**：模拟 GPU 进程重启，看画面能不能自己回来（Electron 里这件事真的会发生）。
- **置顶 (T) / 点击穿透 (P)**：窗口级开关，故意放在键盘上——开了穿透之后页面就收不到鼠标了。
- **读数面板 (H 或右下角 ≡)**：默认收起来，因为 360 宽的窗口摊开会把她整个盖住。

⚠️ **小窗口带来的新问题**：透明窗口的**空白区域照样会吃掉点击**。现在只有 360×576，
她身体之外那一片都会挡住你的桌面——按 `P` 可以全局穿透来确认这一点。
正式桌宠必须做**区域穿透**（鼠标在她身上才收事件，其余位置透下去），
Electron 的 `setIgnoreMouseEvents(true, { forward: true })` 配合渲染层做命中判定就能实现；
要不要现在就做成可切换的一档，见下面"还没定"。

## 什么时候把检查收回来

触发点是"它开始承载正式行为"，不是某个日期：**当这个目录里出现她的形象、订阅 WS 事件、
或进入打包流程时**，把 `pet/**` 从 eslint 的 `ignores` 和 `.prettierignore` 里移出，
跑一次 `lint --fix` 收干净，再继续长。在此之前不碰风格。

`node_modules` 不用管：根 `.gitignore` 里的 `node_modules/` 规则不限层级，这份也覆盖到了。
源码是要提交的。
